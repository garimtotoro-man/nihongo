# 쇼츠말고 니혼고 — 개발 계획서

> 세로로 넘겨보는 숏폼 방식으로, 쇼츠 보듯 일본어를 익히는 학습 앱
> _작성 기준: 비개발자 · 바이브 코딩(AI 도구로 개발) · 초기 비용 0원_

---

## 1. 개요

**한 줄 정의.** "쇼츠 볼 시간에 니혼고 한 장." 숏폼 피드처럼 세로로 스와이프하며 일본어 단어·표현·팁을 자연스럽게 흡수하는 학습 앱.

**문제의식.** 초보자는 단어장·교재를 펴는 것 자체가 부담이다. 반면 쇼츠·릴스는 아무 부담 없이 몇십 개씩 넘겨본다. 그 습관의 형태(세로 스와이프, 짧은 호흡, 즉각적 보상)를 그대로 빌려와 "공부"를 "소비"처럼 만든다.

**목표 수준.** JPT 3급(옛 JLPT 3급 ≈ N4, 초급~초중급). 회화에서 바로 쓰는 단어·표현 중심.

**핵심 차별점.**
- 능동 학습 장치: 카드마다 뜻이 가려져 있고 **탭해야 열린다**(스스로 떠올리게 → 기억에 남음).
- **목적별 테마팩**: 여행·연애·쇼핑·시험 등 내 목적을 고르면 그 단어가 더 자주 나온다(→ 5장 참고).
- 발음 즉시 듣기(브라우저 내장 음성, 비용 0원).
- 마음에 든 단어는 🔖 저장 → 나중에 복습.
- 그냥 넘겨도 노출·반복으로 익숙해지는 구조.

## 3. 핵심 컨셉과 화면

```
┌───────────────────────┐
│ 쇼츠말고 · 日本語   3/20│  ← 상단: 브랜드 + 진도
│  🧳 여행 ▾            │  ← 현재 테마팩(누르면 변경)
│                       │
│   [뱃지] 여행·주문      │
│      いくらですか        │  ← 큰 일본어
│      いくらですか        │  ← 읽는 법
│      ikura desu ka    │
│                       │
│   ▒▒▒ 탭하여 뜻 확인 ▒▒│  ← 뜻은 가려짐(능동 학습)
│                       │      🔊 발음
│   [예문 카드]          │      ♥ 좋아요
│                       │      🔖 저장
│  🔖 3 저장함    ︿ 위로 │
└───────────────────────┘
     ↑↓ 세로 스와이프로 다음/이전
```

**카드 3종류로 피드에 리듬을 준다.**
1. **단어(語)** — 한 단어 + 예문
2. **표현/문장(文)** — 회화 표현 + 예문
3. **팁(💡)** — 문법·문화 한 줄 상식 (지루함 방지, 쉬어가는 카드)

- [ ] **계정 & 기기 간 동기화** (Supabase Auth)
- [ ] **학습 통계** — 요일별·주간 학습량, 정답률 추이, 팩별 진도
- [ ] **푸시/리마인더** — "오늘 니혼고 아직이에요"
- [ ] **테마팩 확장** — 심화·특수 팩 추가(비즈니스·시험 심화 등)
- [ ] **소셜 요소(선택)** — 친구 스트릭, 주간 랭킹
- [ ] **수익화(선택)** — 무료(기본 팩) + 구독(전체 팩·복습·통계)

## 5. 목적별 테마팩 (핵심 콘텐츠 전략) ★

**왜 필요한가.** "왜 일본어를 배우는가"는 사람마다 다르다. 여행 가려는 사람에게 시험 어휘를, 시험 준비생에게 연애 표현을 아무리 밀어봤자 안 남는다. **목적을 고르면 그 목적에 맞는 단어가 더 자주 나오게** 하면, 같은 시간을 써도 "나한테 쓸모 있는" 단어부터 쌓인다. 몰입과 지속의 핵심 장치다.

### 작동 방식
1. **온보딩/상단 버튼에서 목적(팩)을 고른다** — 복수 선택 가능 (예: 여행 + 쇼핑).
2. 카드마다 `packs` 태그가 붙어 있다 (한 카드가 여러 팩에 속할 수 있음. 예: `すみません`은 여행·쇼핑·일상 공통).
3. **피드가 선택 팩 카드를 더 자주 섞어 보여준다**(가중치). 나머지도 가끔 섞어 시야를 넓힌다.
   - 권장 비율: **선택 팩 70% + 전체 랜덤 30%** (목적엔 집중하되 편식은 막는다).
4. 언제든 팩을 바꾸거나 추가할 수 있다.

### 테마팩 예시

| 팩 | 언제 쓰나 | 대표 단어·표현 (예) |
|---|---|---|
| 🧳 **여행** | 일본 여행·길찾기·주문 | すみません(실례합니다) · いくらですか(얼마예요?) · どこですか(어디예요?) · トイレ(화장실) · 助けて(도와주세요) |
| 💕 **연애** | 데이트·호감 표현 | 好き(좋아해) · 会いたい(보고 싶어) · 一緒にいたい(같이 있고 싶어) · デート(데이트) · 付き合う(사귀다) |
| 🛍 **쇼핑** | 매장·계산·사이즈 | これください(이거 주세요) · 試着(입어보기) · 安い(싸다) · カード(카드) · 袋(봉투) |
| 📝 **시험(JPT·JLPT)** | 시험 대비 빈출 | しかし(그러나) · つまり(즉) · 必要(필요) · 経験(경험) · 청해·독해 빈출 어휘 |
| 🍜 **식당·카페** | 주문·계산 | 注文(주문) · おすすめ(추천) · お会計(계산) · 水(물) · 美味しい(맛있다) |
| 💼 **비즈니스** | 직장·격식 표현 | お世話になっております(신세지고 있습니다) · 会議(회의) · 資料(자료) · よろしくお願いします(잘 부탁드립니다) |
| 📺 **애니·드라마** | 자막 없이 듣기 | やばい(대박/큰일) · まじで(진짜?) · 仕方ない(어쩔 수 없다) · 大丈夫(괜찮아) |

> 처음엔 **여행·연애·쇼핑·시험 4팩**으로 시작하고, 반응을 보며 식당·비즈니스·애니 팩을 추가하는 것을 추천.

### 무료로 지금 붙이는 법 (서버 없이)
1. 각 카드 데이터에 `packs` 필드만 추가한다 (아래 6장 스키마).
2. 상단에 팩 선택 버튼 몇 개를 만든다.
3. 피드를 만들 때 "선택 팩 카드 + 일부 랜덤"을 섞어 순서를 짠다.
→ **파일 하나 안에서 그대로 가능**. 데이터가 늘면 나중에 DB로 옮긴다.

### 확장·수익화 연결(선택)
- **기본 팩(여행·일상)은 무료**, 심화 팩(시험 심화·비즈니스)은 프리미엄으로 두는 방식이 자연스럽다.
- 팩은 "주제 콘텐츠 단위"라 **제작·판매·업데이트를 팩 단위로** 굴리기 좋다.

## 7. 데이터 구조

**콘텐츠 카드 스키마** (지금은 코드 안 배열 → 나중에 DB 테이블)
```json
{
  "id": "ikura-desu-ka",
  "type": "phrase",          // word | phrase | tip
  "level": "N4",
  "packs": ["travel", "shopping"],   // ★ 목적 태그(복수 가능)
  "category": "주문",
  "jp": "いくらですか",
  "kana": "いくらですか",
  "romaji": "ikura desu ka",
  "ko": "얼마예요?",
  "example_jp": "これ、いくらですか？",
  "example_ko": "이거 얼마예요?"
}
```

**사용자 진도 스키마**
```json
{
  "user_id": "…",
  "active_packs": ["travel", "shopping"],   // ★ 선택한 목적
  "liked": ["ganbatte"],
  "saved": ["oishii"],
  "seen_count": 132,
  "streak": 5,
  "last_studied": "2026-08-19",
  "quiz": { "correct": 40, "total": 55 }
}
```
> 1차는 이 진도를 **브라우저(localStorage)** 에 저장(무료). 3차에서 **Supabase** 로 옮기면 여러 기기 동기화·로그인이 된다.

## 8. 기술 스택 & 비용 (핵심: 단계별로 필요할 때만 추가)

| 단계 | 무엇 | 도구 | 비용 |
|---|---|---|---|
| **0. 현재** | HTML 파일 1개로 완성된 앱 | 순수 HTML/CSS/JS | **0원** |
| **1. 배포** | 인터넷에 무료 공개 | **Vercel** 또는 Netlify (파일 끌어다 놓기) | **0원**(무료 티어) |
| **2. 정리** | 코드 구조화·확장 대비 | (선택) React/Next.js | 0원 |
| **3. 데이터** | 로그인·기기 동기화·콘텐츠/팩 관리 | **Supabase**(DB+Auth) | **0원**(무료 티어)~ |
| **4. 발음 고도화** | 더 자연스러운 음성(선택) | 브라우저 TTS(무료) → 필요 시 유료 TTS | 0원~ |
| **5. 알림/결제** | 리마인더·구독 | 웹푸시(무료) / 결제 PG | 사용량 기반 |

**원칙:** 지금은 파일 하나로 충분하다. **사용자·데이터가 실제로 생긴 뒤에** Vercel → Supabase 순으로 붙인다. 미리 복잡하게 만들지 않는다.

## 9. 개발 로드맵 (바이브 코딩 기준)

> "몇 주"가 아니라 "무엇을 끝내면 다음"이라는 **완료 조건 중심**으로.

**1주차 — 피드 완성 & 공개**
- 현재 프로토타입을 손에 익히기 → 콘텐츠 30~50장으로 늘리기
- Vercel에 무료 배포 → 링크로 휴대폰에서 직접 써보기

**2주차 — 목적별 테마팩**
- 카드에 `packs` 태그 부여, 상단 팩 선택 버튼 + 가중치 피드
- 온보딩(목적+레벨 선택) 추가

**3주차 — 재미 & 학습 강화**
- 스트릭·오늘의 목표
- 저장함 → 복습(플래시카드), 피드 중간 퀴즈 카드

**4주차 — 지속 장치**
- 콘텐츠 100장+ 확충(팩별로)
- (필요 시) Supabase 붙여 로그인·동기화

각 단계 끝엔 **주변 3명에게 써보게 하고 피드백**을 받는다. "어느 팩이 좋았는지 / 어디서 지루했는지"가 다음 우선순위를 정한다.

## 10. 바이브 코딩 실전 팁

AI에게 요청할 때 이렇게 하면 결과가 좋아진다.

- **한 번에 하나씩.** "테마팩 선택 기능 추가해줘"처럼 작은 단위로. 큰 덩어리는 잘 깨진다.
- **현재 파일을 함께 준다.** "이 파일에 이어서, ○○만 바꿔줘."
- **원하는 동작을 사용자 입장에서 말한다.** "여행 팩을 고르면 여행 단어가 70% 정도 나오게" 처럼 구체적으로.
- **바꾸기 전 백업.** 파일을 복사해 두고 수정(되돌리기 쉽게).
- **콘텐츠와 코드를 분리.** 단어는 항상 파일 맨 위 배열에만 모아둔다(비개발자가 코드 안 건드리고 단어·팩만 추가 가능).
- **막히면 에러 메시지를 그대로 붙여넣어** 물어본다.

## 11. 콘텐츠 제작 계획

- **구성 축 2개:** ① 목적(팩: 여행/연애/쇼핑/시험…) ② 종류(단어/표현/팁). 카드마다 이 둘을 태그한다.
- **범위:** JPT 3급(N4) 회화 빈출 우선. 교재 순서가 아니라 "실제로 자주 쓰는 것" 순서.
- **카드 비율(권장):** 단어 50% · 표현 35% · 팁 15% (팁이 피드에 리듬을 준다).
- **팩 제작 순서(권장):** 여행 → 쇼핑 → 연애 → 시험 → (식당·비즈니스·애니). 수요 크고 만들기 쉬운 것부터.
- **품질 기준:** 발음(かな)·로마자·뜻·예문이 자연스럽고 정확할 것. 예문은 짧고 실제 대화체로.
- **주의:** 남의 교재·앱 문장을 그대로 베끼지 말 것(저작권). 직접 작성하거나 공개 예문을 참고해 새로 쓴다.

| 브라우저 발음이 기기마다 다름 | 일단 무료 TTS로, 반응 좋으면 유료 음성 검토 |
| 초기부터 과설계 | 0단계(파일 1개) 유지, 데이터가 생긴 뒤에만 서버 추가 |
| 혼자 지속 어려움 | 주간 소규모 테스트로 동기·우선순위 유지 |
